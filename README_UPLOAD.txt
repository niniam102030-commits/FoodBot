راهنمای آپلود این پوشه روی گیت‌هاب
====================================

۱) وارد سایت github.com شوید و مخزن FoodBot خود را باز کنید.

۲) روی «Add file» و بعد «Upload files» کلیک کنید.

۳) محتوای همین پوشه را باز کنید و همه فایل‌ها به جز این دو فایل
   راهنما را با موس بکشید و در صفحه گیت‌هاب رها کنید:
   - README_UPLOAD.txt (این فایل — نیازی به آپلود نیست)
   - env_sample.txt  ← این فایل فقط نمونه است! آپلودش کنید ولی
     مسئول سرور باید آن را به «.env» تغییر نام دهد و مقادیر واقعی
     داخلش بنویسد (به‌خصوص BOT_TOKEN واقعی ربات).

   نکته: پوشه .github (شامل workflows) هم باید آپلود شود —
   مسئول ساخت خودکار بسته اجرایی است. در گیت‌هاب برای آپلود
   پوشه، فایل‌های داخلش را با مسیر آپلود کنید (Upload files
   پوشه .github/workflows را می‌سازد اگر فایل را همان‌جا رها کنید؛
   ساده‌تر: از گزینه «Add file → Create new file» و نوشتن مسیر
   .github/workflows/docker-publish.yml و پیست محتوای فایل).

۴) در کادر پایین صفحه بنویسید: First version of FoodBot
   و دکمه سبز «Commit changes» را بزنید.

۵) اگر فایل‌های دیگری مثل .env یا فایل دیتابیس (.db) هم انتخاب
   شده‌اند، حتماً قبل از رها کردن آنها را از لیست حذف کنید —
   حاوی اطلاعات حساس هستند.

اجرای ربات روی سرور (برای مسئول سرور)
====================================

git clone https://github.com/niniam102030-commits/FoodBot.git
cd FoodBot
# فایل env_sample.txt را به .env تغییر نام دهید و توکن واقعی را بنویسید:
mv env_sample.txt .env
nano .env        # یا هر ادیتور دیگر — BOT_TOKEN را پر کنید
docker compose up -d --build

ربات حالا ۲۴ ساعته اجرا می‌شود و بعد از ری‌استارت سرور هم
خودکار بالا می‌آید (تنظیم restart: unless-stopped در docker-compose).

آپدیت نسخه بعدی
===============
روی کامپیوتر: Add file → Upload files → فایل عوض‌شده را رها کنید → Commit.
روی سرور:
cd FoodBot
git pull
docker compose up -d --build
