# ربات FoodBot 🤖

ربات سفارش غذا برای بله — اجرای ۲۴ ساعته روی سرور با داکر.

## دو روش استقرار

**روش ۱ — از روی سورس (فقط برای سرور خود مالک):**
`git clone` + `cp env_sample.txt .env` + `docker compose up -d --build`

**روش ۲ — از روی بسته اجرایی (برای تحویل به اشخاص ثالث):**
سورس کد داخل بسته وجود ندارد؛ فقط `docker-compose.server.yml` و `.env` لازم است.
راهنمای کامل: فایل `README_SERVER.txt` در بسته تحویل.
هر push به شاخه main، بسته اجرایی جدید را خودکار در انبار خصوصی (GHCR) منتشر می‌کند.

## 🚀 اجرای اول (بار اول روی سرور)

### ۱) دریافت پروژه

```bash
git clone https://github.com/niniam102030-commits/FoodBot.git
cd FoodBot
```

> اگر مخزن خصوصی (Private) است، گیت‌هاب از شما نام‌کاربری و یک
> Personal Access Token می‌خواهد — از مالک پروژه توکن بگیرید.

### ۲) ساخت فایل تنظیمات (env)

فایل نمونه را کپی کنید و مقادیر واقعی را داخلش بنویسید:

```bash
cp env_sample.txt .env
nano .env
```

این مقادیر را پر کنید:

| متغیر | توضیح | مثال |
|---|---|---|
| `BOT_TOKEN` | توکن ربات (از @BotFather یا پنل ربات) | `123456:AA...` |
| `API_URL` | آدرس API (برای بله همین بماند) | `https://tapi.bale.ai` |
| `ADMIN_IDS` | آی‌دی عددی ادمین‌ها، با کاما جدا | `123456789,987654321` |

ذخیره: `Ctrl+O` سپس `Enter`، خروج: `Ctrl+X`

### ۳) اجرای ربات

```bash
docker compose up -d --build
```

تمام! ربات اجرا شد. برای اطمینان لاگ‌ها را ببینید:

```bash
docker compose logs -f
```

اگر این خط را دیدید، همه‌چیز سالم است:

```
MFIH Food Bot is running...
```

(برای خروج از نمایش لاگ: `Ctrl+C` — ربات متوقف نمی‌شود، فقط نمایش لاگ می‌بندد.)

```bash
cd FoodBot

```

دیتابیس و لاگ‌ها روی خود سرور در پوشه‌های `pgdata/`، `backups/` و `logs/` هستند و با آپدیت از بین نمی‌روند.

---

## 🗄️ دیتابیس (PostgreSQL)

از این نسخه، داده‌ها روی **PostgreSQL** ذخیره می‌شوند، نه SQLite. سرویس `db`
داخل همان `docker-compose.yml` تعریف شده و هنگام `docker compose up` خودکار
کنار ربات بالا می‌آید؛ داده‌ها در پوشه `pgdata/` ماندگار می‌مانند و بکاپ روزانه
(ساعت ۳ بامداد) با `pg_dump` در پوشه `backups/` ساخته می‌شود — ۷ نسخه اخیر نگه داشته می‌شود.

اگر از نسخه قدیمی SQLite داده دارید و می‌خواهید منتقل شود، یک بار اسکریپت مهاجرت را اجرا کنید:

```bash
python migrate_sqlite_to_postgres.py
# یا با مسیر دلخواه و اجبار به بازنویسی:
python migrate_sqlite_to_postgres.py --source sqlite:///./data/foodbot.db --force
```

## 🛟 ربات چطور ۲۴ ساعته می‌ماند؟

- بعد از کرش → خودکار ری‌استارت می‌شود (`restart: unless-stopped`)
- بعد از ری‌استارت سرور → خودکار بالا می‌آید
- اگر هنگ کند → سرویس `autoheal` هر ۹۰ ثانیه‌اش را می‌فهمد و ری‌استارتش می‌کند
- موقع build → کل کد یک بار تست می‌شود؛ اگر کتابخانه‌ها ناسازگار باشند ایمیج ساخته نمی‌شود و ارور واضح می‌بینید

## 🔧 دستورات پرکاربرد

```bash
docker compose logs -f          # دیدن زنده لاگ‌ها
docker compose restart          # ری‌استارت ربات
docker compose down             # توقف کامل
docker compose up -d --build    # اجرا / اجرای مجدد بعد از آپدیت
docker compose ps               # وضعیت (باید Up (healthy) باشد)
```

## 🚨 عیب‌یابی سریع

**ربات اجرا نمی‌شود / پشت‌سرهم ری‌استارت می‌شود؟**
```bash
docker compose logs -f --tail=100
```
خطای قرمز آخر را ببینید. شایع‌ترین علت‌ها:
- توکن اشتباه در `.env` → توکن را دوباره چک کنید
- فراموش کردن ساخت `.env` → `cp env_sample.txt .env` و پر کردن مقادیر

**موقع `--build` ارور داد؟**
- این یعنی «آزمون ورود» جلوی ایمیج معیوب را گرفت — متن ارور را به توسعه‌دهنده ربات بدهید.

**ربات پیام نمی‌دهد ولی healthy است؟**
- `ADMIN_IDS` را چک کنید و مطمئن شوید کاربر اول یک بار ربات را استارت کرده است.

## 📁 ساختار پوشه‌ها

| مسیر | توضیح |
|---|---|
| `pgdata/` | داده‌های دیتابیس PostgreSQL — **دست نزنید، بکاپ مهم است** |
| `logs/` | لاگ‌ها (چرخشی، حداکثر ۵ مگابایت × ۴ فایل) |
| `backups/` | بکاپ‌های خودکار روزانه (`foodbot_*.sql`) |
| `.env` | تنظیمات محلی — هرگز در گیت‌هاب قرار نگیرد |

## ✨ امکانات تازه این نسخه

- **بکاپ آمار ماهانه برای ادمین‌ها:** در ایام بازهٔ ثبت‌نام هر شب یک اکسل آمار ماه به
  ادمین‌ها ارسال می‌شود؛ خارج از بازه فقط اگر ادمین همان روز ثبت‌نام را دستی فعال کند.
- **گزارش آشپزخانه:** اکسل تعداد پرس هر غذا به‌تفکیک روز، بدون ظرف یکبار مصرف و غذای آزاد.
- **یادآوری هوشمند:** از ابتدای بازه هر روز، و در آخرین روز هر ۸ ساعت؛ اگر کاربر ناهار
  را ثبت کرده باشد هیچ یادآوری‌ای (حتی برای شام) دریافت نمی‌کند.
- **اعلان تغییر منو و قیمت:** هنگام ویرایش نام غذا یا قیمت (غذا/ظرف) به همه کاربران اطلاع داده می‌شود.
- **تاریخچهٔ شخصی کاربر:** دکمهٔ «📜 تاریخچه من» در منوی اصلی؛ خلاصهٔ ثبت‌های هر ماه.
